Detailed Description

Represents a data-oriented material system within the Andromeda Engine.

  • This class bundles shader parameters (uniforms) and textures for a renderable object. In contrast to traditional object-oriented approaches, this class stores all shader data (such as floats, vectors, and matrices) contiguously inside a single, flat byte buffer (m_CpuStorage).
  • Note
    String lookups via the internal translation table (m_UniformTable) occur exclusively when setting parameters. The performance-critical render path (bind) is completely free of hash maps and string lookups, guaranteeing maximum CPU cache locality.

◆ bind()

void Andromeda::Material::bind ( IGraphicsContext * ctx) const
inline

Binds the material and uploads all parameters to the GPU in a highly efficient batch.

  • This method is called every frame inside the render loop. It builds a flat submission queue (UniformData) directly on the CPU stack, containing pointers into the contiguous byte buffer. The data is then submitted to the RHI via a single batch call.
  • Parameters
    ctxPointer to the active graphics context (RHI) handling the data upload.

◆ setParameter()

template<typename T>
void Andromeda::Material::setParameter ( const std::string & name,
const T & value,
ShaderDataType type )
inline

Sets or updates a shader parameter within the contiguous memory buffer.

  • The function looks up the GPU location by the variable's name. If the parameter already exists, its raw bytes are directly overwritten at its current offset. If it is a new parameter, the buffer is dynamically resized and the data is appended to the end.
  • Template Parameters
    TThe C++ data type of the value (e.g., float, glm::vec3, glm::mat4).
    Parameters
    nameThe exact name of the uniform variable within the GLSL shader code.
    valueThe actual data value to be passed to the shader.
    typeThe corresponding platform-agnostic shader data type.
  • Note
    If a variable is declared in the shader but never used inside its main() function, the graphics driver's optimizer will strip it out. In this case, this function will bail out early since the variable won't exist in the reflection table.
